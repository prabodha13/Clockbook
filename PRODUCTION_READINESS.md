# ClockBook production-readiness matrix

This report distinguishes source-code controls from operational proof. A control is not marked Closed merely because code exists.

| Area | Status | Evidence | Remaining risk | Recommended action |
| --- | --- | --- | --- | --- |
| Authorization / object access | Closed for current reviewed paths | Server-side role/pod/object checks; tenant query/write isolation; regression tests for staff/admin/tenant boundaries | New endpoints could regress scope if added carelessly | Keep authorization tests mandatory in CI for new protected routes |
| Timer concurrency / idempotency | Closed for current timer model | DB one-running invariant; transactional locks; idempotent Pause/Reset/Complete; concurrent regression tests | Distributed production behavior should continue to be exercised on PostgreSQL | Keep invariant tests and include timer smoke check after deploy |
| Timer data integrity | Acceptable residual risk | Segment-based duration, non-negative duration protection, work-date tests, diagnostics | DST/timezone edge matrix is not exhaustive | Expand date/time boundary tests when timezone behavior changes |
| Tenant isolation | Closed for current reviewed ORM model | Automatic tenant-scoped ORM reads, cross-tenant write guard, cross-tenant regression tests | Raw SQL introduced later could bypass automatic ORM scope | Require explicit tenant/security review for new raw SQL |
| Integration/token security | Acceptable residual risk | Encrypted Google refresh tokens, OAuth state/PKCE, tenant-specific optional integrations, safe disconnect behavior | External provider failure matrices are not exhaustive | Keep integration failures non-fatal; add provider fault tests as integrations evolve |
| Concurrent admin editing | Closed for reviewed shared configuration | SQLAlchemy optimistic versions plus integration configuration revisions; stale writes return 409 | New shared config tables may omit versioning | Apply concurrency review checklist to each new admin-managed model |
| Audit logging | Closed for ORM business/configuration mutations reviewed | Tenant-scoped append-only audit_events, secret exclusions, audit regression tests, coverage review | Direct DB changes remain outside app ledger; task state logging stays intentionally concise | Restrict/log production DB admin access and periodically review audit coverage |
| Request validation | Acceptable residual risk | `extra=forbid`, 2 MiB body limit, bounded common/high-risk fields/lists/numbers/enums, tests | Future schemas can introduce unbounded fields | Add schema negative tests for new public endpoints |
| Automated regression/invariant testing | Closed for current critical source controls | Persistent pytest suite covers auth boundaries, tenant isolation, timer races/idempotency, export, templates, capacity, integrations, audit/concurrency; property suite included for CI | Cannot guarantee every workflow; frontend E2E still limited | Keep CI required before merge; add tests with every bug fix |
| Property testing | Closed for defined invariants | Hypothesis tests for non-negative duration/capacity and constrained authorization domain; deterministic invariant tests | Hypothesis dependency executes in CI, not current minimal local runtime | Keep Hypothesis pinned in CI requirements |
| Database constraints | Acceptable residual risk | Running-timer/client-code/membership/invitation and other critical indexes/constraints; ORM guards | Not every business rule belongs at DB layer | Add DB constraints only for stable cross-request truths |
| Migration framework | Acceptable residual risk | Alembic scaffold/baseline, documented adoption path, migration graph validated in CI | Existing startup DDL remains during transition; production DB not yet stamped/tested | Backup, verify production-like copy, stamp baseline, move future changes to Alembic |

| External uptime monitoring | Operational action required | `/health/live`, `/health/ready`, monitoring runbook | No external alert has been proven | Connect monitor and perform a controlled alert test |
| External error monitoring | Operational action required | Structured request IDs/logs; provider requirements documented | No external exception/alert provider configured | Select provider, connect staging/production, test redaction and alert delivery |
| Dependency / supply-chain scanning | Operational action required | CI workflow includes pip-audit/npm audit; Dependabot config; CI dependencies pinned | Actual production manifests/lockfiles are absent from this source package, so production dependencies are not proven scanned | Commit authoritative production manifests/lockfiles and require CI checks |
| Incident response | Acceptable residual risk | Incident playbook; workspace/global emergency session revocation endpoints | Playbook has not been exercised as a tabletop/incident drill | Run a short cross-tenant/session-compromise tabletop exercise |
| Rollback procedure | Acceptable residual risk | Documented version identification/rollback/schema decision process | Real rollback exercise not evidenced | Test rollback in non-production after a schema-compatible deployment |
| Impossible-state reconciliation | Acceptable residual risk | Existing repair tooling plus new read-only tenant invariant diagnostics | Diagnostic catalogue cannot cover unknown future corruption | Run diagnostics periodically and extend when real anomalies are found |
| Performance / N+1 baseline | Outstanding | Performance measurement plan documented; indexes already improved earlier | No representative PostgreSQL load benchmark has been evidenced | Seed production-like non-prod dataset and capture p50/p95/query counts |
| Accessibility / browser validation | Operational action required | Practical Chrome/Edge/keyboard/zoom checklist exists | No completed signed-off test record | Run checklist for release candidate and record versions/results |
| Engineering documentation | Acceptable residual risk | Architecture, tenancy, auth, timer, template, integration, audit, deployment/migration/ops docs now consolidated | Documentation can drift | Update docs in same PR as material architecture changes |

| Historical secret exposure | Operational action required | Current-source posture plus historical review checklist | Git/Railway/CI/log history was not available for complete verification | Review operational history and rotate any uncertain credential |

## Overall conclusion

ClockBook now has materially stronger controls than a typical ad-hoc or AI-generated internal application: tenant isolation, object authorization, database timer invariants, idempotent state transitions, optimistic administrative concurrency, append-only application auditing, strict input boundaries, regression/invariant testing and documented operational controls are all present.

It should **not** yet be described as fully operationally hardened. The remaining blockers are primarily evidence and operations rather than another product-code redesign: complete a real backup/restore drill, wire and test external uptime/error monitoring, bring authoritative production dependency manifests under scanning, run a production-like performance baseline, complete browser/accessibility validation, and review historical secret exposure.
